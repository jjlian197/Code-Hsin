# 桌面精灵工程经验

先确认目标项目的角色管线与当前任务。Hsin 的 PMX/MMD/Three.js 方法不能直接套到 Aemeath 的 GLB 或 Live2D；只迁移适用的不变量，不为使用经验而重写现有架构。优先沿用窗口、托盘、气泡、播放、控制接口和本地配置；保留用户已有 Agent、语言与凭据。

根据实际改动选择参考：

- 模型、手势、站立/侧躺、布料、近景与触摸：读 [角色动作与取景](references/character-motion.md)。
- 分句朗读、逐句气泡、预热、取消、麦克风及默认互动状态：读 [语音与陪伴](references/speech-companion.md)。
- EXE、新用户配置、资源清单与正式发布：读 [可迁移发行](references/distribution.md)。

把“指令接收”“短句排队”“实际播放”“模型实际姿态”区分开。界面和结论以可观察状态为准：HTTP 成功不代表模型已完成过渡，已合成不代表声音正在播放。记录支持结论的最小证据，避免用延迟模拟后端证明真实首句延迟已解决。

停止、切换、模型加载、音频解码和退出是常见边界。先明确旧任务如何失效，再接入新行为；有明确代次/请求标识的代码不要只靠布尔 busy。只做请求需要的修改与验证；原生窗口、私有模型、真实音频检查在隔离状态和端口下执行，不开启用户麦克风、不覆盖当前配置。

这里的数值来自 Hsin 的已验证实现，可作为调试起点，不是所有角色的标准。发布、上传、消息或修改 Aemeath 本身仍按当前用户授权执行；使用 Skill 不自动授权这些操作。
