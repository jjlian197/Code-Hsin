## 已准备的实验入口

设置与右键对话后端菜单新增“Qwen · 本机聊天（实验）”，模型名称默认指向用户已有4B。普通回复默认关闭思考，简短/适中/详细分别使用768/1536/4096生成token；高级设置可开启思考（4096生成预算）。上下文预算单独配置，默认4096。连接仅接受本机HTTP地址，缺模型报错，不下载、不切云端补救。

本机聊天使用应用现有ChatManager、分句及代次取消。思考不进入正文、气泡或朗读；中断与生成上限有明确状态，只有完成的对话进入后端历史。当前没有工具执行权限，不能把这一入口当作已有Hermes工具Agent的替代。

选择Qwen后，自动翻译也走同一Ollama模型，不读取云端Key；本机与云端翻译缓存隔离。菜单切换、重启恢复及统一设置更新后，翻译随实际聊天后端切换。音色和听写仍是独立引擎设置，选择Qwen聊天不等于全部离线。

Qwen听写与音色现已接入源码设置和右键菜单。ASR/TTS分别使用独立Python环境中的常驻子进程；热词传入ASR context，中文使用epoch3微调检查点，日文使用官方Base和既有参考原声。停止或切换时取消运行中的旧任务，Qwen失败明确提示，不回退云识别或Edge。默认后端不变，当前EXE尚未重新打包。

隔离配置与资源清单位于 `.runtime/local-model-tests/acceptance/`。配置只沿用角色资源，不复制云端凭据；不开控制端口、语音关闭、麦克风默认关闭。会话状态与设置写在独立目录，不改日常配置。

```powershell
# 核对已有资源并准备配置，不下载、不启动模型。
python tools/prepare_qwen_acceptance.py

# 自动验证真实窗口、PMX加载、中日聊天、生成中取消后重发和本地翻译。
python tools/verify_local_chat.py

# 启动独立窗口，手动测试4B聊天。退出窗口后清理本次模型服务。
python tools/run_local_acceptance.py

# 启动完整Qwen语音实验窗口；麦克风默认关闭，由用户主动开启。
python tools/run_local_acceptance.py --voice

# 用既有合成录音验证真实窗口完整链路与后台取消，不开麦克风。
python tools/verify_qwen_voice.py

# 后续8GB阶段；此命令只检查聊天与PMX。
python tools/verify_local_chat.py --gpu 8gb
```

需要已安装的Ollama及用户已有模型。验收实例使用11435；已有11434服务保持原样。端口被占用就停止，不结束其他服务。Windows退出先卸载模型，再清理本次进程树。
