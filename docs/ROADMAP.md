## v1.4.0 已接入与下一版本计划

本轮源码已接入“跑步（半速）”：用户提供的 `Treadmill Running.fbx` 重定向到心的双形态，单次约15.73秒，结束恢复待机；从侧躺选择时先起身，再执行跑步。心的已验证原版模型加载时默认应用十根胸部辅助骨改绑及物理后标记，并保留现有胸部补偿，效果对应用户选择的“改模 + 关闭原生胸物理”。原始PMX文件不改写，复杂手势和过渡仍使用原有匹配检查。v1.4.0包含这些改动，详见[物理后与跑步说明](PMX_POST_PHYSICS.md)。

后续按以下顺序推进，先完成角色导入体验，再精修动作；这些优化目前属于计划。

爱弥斯1.05 PMX已追加独立胸部适配：按其六刚体结构调整第二段父骨骼、物理后标记及受限旋转补偿，支持原版自动适配和独立改骨副本。四组跑步对照、角色包表情及五元音检查通过，见[爱弥斯胸部说明](AEMEATH_CHEST_PHYSICS.md)。现已接入挥手、V手势、比心、X手势及半速跑步，按实际指尖末端骨和上胸校准；躺下仍禁用。

### 目标与基准

用户有大量 PMX 模型，希望通过一键匹配骨架，批量制作新角色桌面精灵。按“开发骨架匹配脚本”讨论中的最终决定，**以 Hsin 项目为标准**，将骨架整合器逐步发展为 Hsin Character Import Pipeline。爱弥斯后续作为待迁移角色向 Hsin 优化，不把其难以维护的历史资产和角色专属逻辑作为标准。

目标流程：`导入 PMX → 分析骨架 → 匹配 Hsin Standard Rig → 校正缺失与冲突 → 生成角色包 → Hsin Runtime 预览`。脚本、独立骨架校正、基础运行时访问与本地角色包生成/加载已打通；拖放/一键生成界面、更广泛的模型适配和动作重定向继续开发。

### 分步实施与验收

1. **定义 Hsin Standard Rig Schema**：从当前 Hsin 运行时实际需要调用的骨骼语义出发，区分核心人体骨、可选骨、手指、眼睛、IK 与头发/裙摆物理骨；表情另用 Morph 映射描述。明确必需项、可选能力及缺失时的处理方式，避免把 Hsin 某个模型的具体骨名直接当成通用标准。
2. **PMX Analyzer 与自动匹配**：读取骨名、父子拓扑、骨骼位置、左右侧、相对骨长和骨轴；先用日文 MMD 标准名、英文、中文及常见别名匹配，再结合拓扑与空间关系处理自定义名称。输出匹配依据、置信度、缺失项、重复映射和左右冲突；高置信度自动采用，低置信度或冲突项留给人工校正，不以单纯改名代替适配。
3. **生成 `rig_map.json` 与运行时适配层**：尽量保留原 PMX 的骨名、结构、蒙皮、IK 和物理，通过旁置映射文件将 Hsin 语义骨关联到模型实际骨骼，并保存人工修正以便复用。运行时通过映射访问骨骼；先让现有 Hsin 双形态走同一映射入口，确认现有动作、表情和物理表现保持正确，再扩展新角色。
4. **角色包与角色配置基础版已完成**：v1 保存模型/贴图引用、骨架/Morph 映射及能力清单；设置中的角色管理绑定人设、后端和TTS，支持保存、完整切换与启动恢复。爱弥斯待机、视线、表情与五元音通过原生检查；挥手、V、比心、X和跑步已接入；躺下、其他全身动作、通用触摸、真实新音色及音频口型时序继续适配。
5. **动作适配与校准**：先接 VPD/VMD，按“源动作 → 标准语义动作 → 目标 PMX”逐步适配；骨架匹配完成后仍需处理初始姿势、骨轴、骨长、Grant、IK、根位移及接触约束。重点检查手指与比心、掌面朝向、脚底/地面高度、躺下/起身和衣发物理；现有为 Hsin 校准的过渡不能直接宣布兼容任意角色。FBX/CMU 等动作源后续按需求扩展。
6. **扩展与爱弥斯迁移**：原型稳定后评估 Morph 自动映射、材质规范化、物理骨分类、缩放/地面校准及兼容性评分；爱弥斯通过同一角色包与运行时逐步迁移，清理角色专属适配的工作单独安排，不在本轮整理 ROADMAP 时修改其他项目。

首轮验收以 Hsin 双形态和用户选择的不同骨架 PMX 为样本，覆盖标准命名、自定义命名与缺失可选骨。确认映射无重复/左右颠倒，人工修正可保存复用，原 PMX 不被覆盖；在实际网格预览中检查基础动作、口型与物理，并给出每个模型可用、需校准和暂不支持的能力清单。“一键”以高置信度模型自动完成为目标，疑难模型允许少量人工确认，不预先承诺所有 PMX 或动作零校准。

## 一二阶段自主切换与语气联动（计划，尚未接入）

1. **同一角色、两种日常形态**：一阶段使用轻佻诙谐、灵动狡黠的小狐狸语气，偏向闲聊、触摸、休息与日常关心；二阶段使用正式端庄、从容温柔的岁主语气，解锁后经常参与分析、写作、规划、查资料和工具执行。两阶段共享记忆与关系；二阶段不淘汰一阶段，也不意味着推理模型更强或工具权限增加。
2. **好感度解锁自主切换**：具体关系门槛待定，优先考虑“信赖”阶段。首次解锁不询问用户，以自然台词、形态与声音联动呈现惊喜；解锁事件只呈现一次并保存状态。提供关闭自动切换和手动固定形态的设置，用户选择优先。形态决定基本语气，情绪调节当下表达，好感度调节亲近程度；二阶段也能开心、害羞，一阶段也能认真安慰。
3. **工作情境驱动**：解锁后，明确工作请求触发二阶段，补充、追问、修改、工具执行及结果讨论保持二阶段；明确结束工作或转入闲聊后回到一阶段。意图不明确时保持当前形态，单次触摸、情绪变化或好感度上涨不直接触发变身。后端维护工作状态，模型可提出切换建议，由程序结合解锁状态、用户选择和当前任务决定执行，避免频繁往返。
4. **闲置与切换时机**：二阶段闲置 10 分钟后请求回到一阶段；闲置从当前任务、回复生成、合成与播放全部结束后计时，新互动重新计时。即将切换时，先等待正在生成的回复完成，并完成其后续合成、当前播放及全部待播内容，再执行模型与语气切换，不截断或重新生成当前回复；工具执行、拖动及躺下/起身等动作期间等待安全时机。等待期间发生新互动或用户手动固定形态时重新判断待执行切换，避免过期请求突然变身。
5. **外观驱动文字与声音**：角色外观模型切换是主事件，成功后统一更新回复风格、TTS 配置、表情与动作。对话大模型可以共用，每轮读取共同人设与当前形态的表达要求；过渡台词简短自然，不反复宣布身份，不把岁主语气写成堆砌古语。每句文字与音频绑定生成时的形态，缓存包含形态和参考原声标识，避免播放另一阶段的旧缓存。
6. **TTS 与验收**：为中日两种语言分别准备一阶段俏皮、二阶段端庄的参考原声，保留两阶段原声已有的音色差异。优先测试 Qwen3-TTS-0.6B-Base 的参考音频语气迁移，不假定其支持自由情绪指令；CosyVoice3-0.5B 为备选，现有 GPT-SoVITS 为对照。检查首次惊喜只触发一次、工作/闲聊与 10 分钟回退、生成和待播队列排空后切换、用户固定形态优先，以及中日语气、音色、表情动作与实际播放同步。
