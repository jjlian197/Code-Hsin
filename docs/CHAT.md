# 和心聊天

开发版回复气泡按句显示：第一句到达就先展示，随后跟随每段音频实际开始播放切换，回复完成不会把全文覆盖进去；完整记录保留在聊天窗口。无语音、未配置语音或选择不自动朗读时，按每秒 6 字逐句推进，短句至少停留 1.8 秒。限制只读前几句/前几字时，未朗读的后续文字在语音结束后按相同速度展示。停止或新对话会取消旧气泡计时，语音失败或中途关闭后改为文字推进。

右键或托盘选择“和心聊天…”，输入文字后回车或点击发送。默认使用本地 **Hermes · Hsin**。右键的“对话后端”可选择 Hermes、OpenClaw 或 DeepSeek 直连；选择保存在 `.runtime/chat.json`。回复逐步显示，完整短句到达后立即排入当前中文或日本語音色的合成队列，播放当前句时继续接收文字和预合成后句。切换语言会取消旧回复；“停止回复”同时停止等待结果、当前播放与未播放的语音，全文收到后此按钮仍可停止朗读。

关闭聊天窗口后，当前回复继续完成。文字记录保留在本次应用运行的窗口中；每个后端维护自己的上下文。DeepSeek 保留最近六轮成功对话，Hermes 通过自己的已保存会话恢复上下文，OpenClaw 使用本客户端独立的 `agent:hsin:desktop-…` 会话。聊天期间拖动、自然动画和物理继续运行。

## 验证与限制

实际中日连续对话记录位于 `.runtime/chat-backend-validation.json`，原生桌面聊天→Hermes→中日合成→播放→PCM 口型报告位于 `.runtime/chat-desktop-validation.json`。开发版正常启动会后台预热当前语言的 GPT-SoVITS；若预热尚未完成，首次开口仍需等待。分句与预热不能保证音频早于文字回复完成；后续同文短句使用缓存。

聊天窗口顶部和统一设置可选择“简短/适中/详细”回复，以及“全文/前几句/前几字/不自动朗读”。默认适中回复、全文朗读，取消原来的累计 500 字上限；前几句可选 1–30，前几字可选 50–10000，字数预算保留完整分段，不硬截半段。范围只影响语音，聊天全文保留；模型仍受自身生成上限和 Agent 配置约束，长度选择不是字数保证。

分句支持中文/日文句号、问号、叹号、换行和英文句点；无标点长句最多约 80 字一段，优先在逗号或空格处切分，以减少首段积压。长句的内部切段不会被算作多个句子。思考标签、代码块、行内代码、图片和链接地址不朗读，链接保留文字。尚未闭合的结构先等待，回复结束后不朗读残缺结构。

“朗读选中内容”与“重读最近回复”按当前语音语言分段排队，支持超过 500 字的正文；手动重读不受自动范围限制，也不改变范围设置。原有“停止回复”在文字结束后仍可停止剩余语音。修改长度或范围会停止当前回复/朗读并保存偏好，后续请求使用新选择。

状态栏明确显示接收文字、合成下一句、正在朗读第几段、达到所选范围或失败。分句朗读是边收文字边合成短句；当前每段仍需合成完整 WAV 才播放，不是单段内部 PCM 逐块播放。音色冷启动或回复生成很快时，第一句仍可能晚于全文完成。真实 Hermes 两轮时序检查均证明首句在全文前送入合成，但实际首段播放都晚于全文；不能用故意延迟的模拟回复替代这个性能结论。

最终回复用于补齐没有通过 delta 传来的尾句，不会重读已排队的前缀。若后端修改了已朗读的前缀，保留最终聊天文字并取消剩余语音，不再播放修订全文。停止语音、静音、切换后端/语言/引擎、发送新消息或任一句失败都会清空队列并使迟到结果失效；当前正在执行的本地推理可能继续完成，但结果不会播放。

播放当前句时最多预合成两句；即使后续合成更快，也要等前句播放结束。每句继续使用原有缓存、备用音色与 PCM 口型。语音回复期间暂停收音，覆盖合成、预备队列和实际播放；麦克风设置见 [STT](STT.md)。后端失败在聊天窗口和 `chat.error` 显示，不自动转向另一个后端。

```powershell
python -m tools.verify_chat_backends hermes deepseek
python -m tools.verify_chat_desktop
python -m tools.verify_streaming_speech
python -m tools.verify_streaming_live
```

分句原生检查使用模拟聊天与本机已训练音色，静音播放、不开麦、不调用远程后端。检查中日首句在最终回复前播放、顺序、无重复、真实音频口型和收音阻塞恢复；报告为 `.runtime/streaming-speech-validation.json`，验证语音缓存为 `.runtime/streaming-tts/`。

真实时序检查使用独立 Hermes 测试会话与心的实际音色，静音播放、不开麦，不人为延迟最终回复；记录文字到达、首句排队、全文完成、首段播放时间，报告为 `.runtime/streaming-live-validation.json`。检查的“通过”表示链路与分句时序正确，不表示每次音频都早于全文。本次另有 51 项针对性检查覆盖长回复、完整保留文字、范围/偏好保存、选中文字重读、停止/切换及生成上限提示。
