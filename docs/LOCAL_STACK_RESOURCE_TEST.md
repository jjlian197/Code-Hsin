# 4080S共同负载与挂机资源检查

2026-10-05，按用户授权，在4080S上同时驻留PMX、官方Qwen3-ASR-0.6B、已有Huihui Qwen3.5 4B和GPT-SoVITS中日音色。真实窗口完成24轮交替语言往返，随后闲置5分钟；窗口内观察776.28秒，约13分钟。24次实际TTS预热、48次实际新音频合成及播放通过，无模型错误或OOM。

## 条件与测量口径

- 使用独立配置、11435/19885端口及独立状态目录；保留用户已有服务、资源和日常配置，不下载模型。
- ASR/TTS/4B以CUDA UUID选择4080S；PMX以DXGI适配器选择同卡，实际WebGL渲染器报告`NVIDIA GeForce RTX 4080 SUPER / D3D11`。Qt显卡选择参考[Qt官方说明](https://doc.qt.io/qt-6/qtquick-visualcanvas-scenegraph-renderer.html)。绑定仅作用于本次测试进程。
- 4B关闭思考、上下文4096、简短回复；PMX全身站立、物理开启，沿用约30帧调度。
- 以既有两段中日合成录音反复注入VAD，不开物理麦克风；真实ASR、聊天、分句、音频解码和播放器链路运行，音量为0。每轮独立音频缓存，保证新合成，不能以缓存播放冒充持续推理。
- 整卡显存约每2秒采样，部分采样受进程检查影响间隔稍长，因此结果是采样峰值。进程内存覆盖本次窗口、Qt子进程和模型子进程；测试监测程序的少量开销也包含在内。
- 驻留内存RSS含共享页，逐进程相加可能重复统计；私有驻留内存USS是仅属于这些进程的实际物理页。虚拟提交量包含其他映射，不能当成实际RAM占用。

4B服务自身报告`size_vram`约2983MiB，但服务报告不包含所有驱动及运行时开销，不能用权重大小替代整套显存测量。Windows逐进程GPU计数器中，PMX的DedicatedUsage不断累计，甚至超过整卡实际用量，而其TotalCommitted不足1GiB；该计数不用于物理显存合计或泄漏判断。[微软记录过类似GPU进程计数误报](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/gpu-process-memory-counters-report-wrong-value)，但本轮不足以确认系统是否属于同一原因。

前后稳定时段整卡显存中位数为12987/13077MiB，相差90MiB；私有物理内存中位数6762/6753MiB，略有下降。语言切换时出现短暂内存峰值，随后回落，未发现本轮负载下持续增长。

闲置接近5分钟时4B自动卸载，整卡显存从13055降到9060MiB，释放约3.9GiB；此时ASR、GPT-SoVITS和PMX仍驻留，项目净显存约5.7GiB、私有物理内存约5.5GiB。退出窗口后本次模型进程全部退出，整卡回到3209MiB。不能据约13分钟、两种短录音与4096上下文推断数小时、长音频、长上下文或8GB设备已经验收。

## 优化顺序

1. **先增加ASR/TTS闲置释放**：当前4B已有5分钟保温，ASR与GPT-SoVITS没有同样的闲置释放。可保留5–10分钟温热期，全部任务、合成与播放队列结束后再释放自己管理的进程，下次使用时重新加载。预计主要收益来自闲置时约5.7GiB的残留占用；释放与再加载的实际节省、等待时间需单独验收，不每句话都卸载。
2. **8GB阶段先比较ASR转CPU**：本轮ASR进程GPU计数约2.1GiB，可作为节省量的参考，但CPU模式的速度与RAM增加尚未实测。仅移走ASR仍可能没有足够桌面和推理峰值余量，需要再比较4B部分CPU运行或主脑/TTS按阶段轮换。当前全部常驻组合超过8GB目标。
3. **保持4096作为日常上下文基线**：已有历史限制为12条消息，TTS预合成队列有上限，避免无界累积；更长上下文只在需要时扩大并重新测量，不把1536输出预算与显存容量混淆。
4. **给音频磁盘缓存设容量或时间上限**：这是长期磁盘占用优化，不直接等于释放RAM。清理必须避开当前播放及待播文件，在队列结束且播放器释放文件后进行；保留固定预存语音、权重与参考原声。
5. **沿用现有渲染节流**：PMX已经约30帧，隐藏时暂停；本轮没有证据要求修改物理、材质或动作。以后可单独比较闲置低帧率对功耗的收益和观感。
