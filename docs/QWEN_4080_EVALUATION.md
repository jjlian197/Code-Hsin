2026-10-05。复用用户现有 Ollama Huihui 4B、9B 权重，未下载第二份模型；ASR、TTS 只加载已有本机资源。Ollama 日志确认使用4080S CUDA、主模型全部层卸载到GPU。隔离端口11435，未改应用默认配置，未开启麦克风。

这些是修改版权重的小样本结果，不代表官方 Qwen3.5 基准成绩，也不能证明8GB设备的共同显存或实际桌面交互延迟。

## 推理与预算

同样的三题：20+15分钟串行与10分钟并行（35分钟）、长并行任务后再执行5分钟（35分钟）、200元打八折再减20元（140元）。温度0、seed42、上下文8192；关闭思考输出上限1024，开启思考4096。思考和最终回答共用输出预算。

| 本机模型 | 关闭思考 | 开启思考 |
| --- | --- | --- |
| Huihui 4B Q4_K_M | 3/3最终答案正确，完整输出；0.61–5.31秒 | 3/3正确，完整输出；2.19–20.76秒 |
| Huihui 9B Q4_K_M | 2/3正确；长并行题漏算D的5分钟 | 3题均达到4096 token上限，最终回答为空；41.06–42.20秒 |

4B原排程题开启思考7.44秒，首段最终文字7.25秒，1084个生成token，`done_reason=stop`。此前1536预算截断未重现。提升预算和更新提示同时发生，不能把正确性改善归因于更大显存；本轮无OOM。各请求包含不同加载/缓存状态，耗时范围不是严格的热机性能比较。

## 人设、翻译与真实工具回合

- 明确专名后，中译日保留“心月狐、Hsin、御者”；日译中保留先完成工作、休息十分钟、再确认的顺序。
- 初版身份说明仍把用户叫作“岁主”。直接写明“用户是御者，称呼只能用御者”后称呼正确，但4B将一小时排成两小时；再限制总预算60分钟后，仍出现“各20分钟”与实际区间不一致。不能视为人设与工作安排已通过。
- 9B在明确预算提示下给出15+20+25分钟，称呼正确。语气仍需用户评估，单条成功不证明稳定性。
- 日语往返初版回复超过两句且表达生硬；全日文人设指令补测甚至复述输入。改成中文明确要求“用自然日语回答问题，不复述或翻译提问”，得到正常的两句休息建议。保留原失败，不强制替换听写内容。
- 工具仅允许写入、读取本次隔离目录的固定便笺。4B真实写入成功，但后续工具解析报`expected element type <function> but have <parameter>`；无参数读取、带固定文件名读取及开启思考复查均未完成完整回合。
- 9B完成真实“写入→读取→根据结果回复”，正确算出25+10=35分钟。原始请求、工具结果、便笺及最终回复均保留。没有调用真实应用计时器或修改用户工作文件。

因此暂时继续以4B作实验基线；9B可作为工具能力对照，不能直接当作更强的通用替代。接入前需要解决连续工具协议和任务约束，不能在解析错误后宣称工具执行成功。

## ASR、TTS与实际播放

使用选定TTS合成中日测试请求，再真实送入Qwen3-ASR，识别文本送入4B，流式输出经过应用现有`SentenceStream`分句，逐句生成WAV，最后由应用现有`LocalVoicePlayer`静音实际解码播放。

- 中文请求转写内容正确，仅标点变化；首次转写4.03秒。日文后续转写0.69秒，但“二文”变成“にむん”。这是合成语音样本，不能据此判断真人麦克风准确率，也未区分错误来自输入TTS读音还是ASR。
- 中文使用epoch3微调检查点；日文使用官方Base与已有参考原声，无减速后处理。共生成中文2段、日文4段回复音频，均为有效有限数值音频。
- 单段合成5.83–14.08秒，音频2.72–7.44秒；目前仍有明显等待。该数字是生成调用耗时，未包含模型加载，不是应用首句端到端延迟。
- 六段均按顺序进入真实播放并结束，PCM缓冲非空，无播放器错误。播放中取消后500毫秒检查仍为停止状态、口型音量为0。
- 真实Ollama流收到思考片段后关闭连接，后续新请求完整回复“收到”。这验证连接取消和后续请求可用，不等于已验证应用代次、后台合成任务取消和旧结果隔离。

此次分阶段检查未实现边生成边合成边播放，也未运行完整PMX窗口、真人收音或8GB共同负载。应用接入后仍须测预热、首句等待、队列、切语言、旧任务取消和断网完整往返。
