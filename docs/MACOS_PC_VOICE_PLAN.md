# macOS → PC 语音推理桥接方案（已确认并实施首版）

2026-10-07：用户已确认方案并要求保留智谱 STT；首版实测与启动方式见 [PC 语音指南](MACOS_PC_VOICE.md)。下文保留设计依据。实际 GPU 为用户追加确认的 RTX 4080 SUPER。

## 参考实现的实际边界

本机 Aemeath spirit visionOS 工作区的 `visionos/Tools/voice_bridge.py` 在 Mac 上提供 HTTP/WS 桥接：客户端提交录音片段，由 Mac 调用智谱 `ZhipuASR`；GPT-SoVITS 合成经配置的 PC 服务完成。WS 按句发送字幕和整段 WAV 音频，并支持心跳、请求编号与对话中断。它目前并未把 STT 本地推理部署到 PC。

可迁移的是录音片段上传、按句音频返回、请求标识和连接管理。Hsin 已有分句、播放队列与代次控制，不需要迁移 visionOS 整套聊天/大脑链路。这里的流式是逐句返回完整 WAV，并非句内 PCM 实时流。

## 建议职责

| Mac | PC（192.168.50.230） |
| --- | --- |
| Qt 麦克风采集、VAD 断句 | Qwen3-ASR 本地识别 |
| 现有聊天后端和回复分句 | GPT-SoVITS 心音色合成；以后可切换 Qwen3-TTS |
| WAV 缓存、Qt 播放、口型、气泡和动作 | 模型环境、权重、参考音频、GPU 与推理排队 |
| 远程 provider、连接状态、超时与旧结果丢弃 | 服务身份、模型能力、作业状态和取消反馈 |

最初环境说明写的是 RTX 4060，盘点后用户已确认使用实际存在的 RTX 4080 SUPER。部署通过实际 GPU UUID 固定设备，禁止使用当前 PyTorch 不兼容的 RTX 5060。现有 `ModelProcess` 的设备名称映射仍含 4080/5060，不能直接复用默认配置；准确 UUID 路径可作为接入基础。

## 首版接入

1. 盘点 PC 的 Hsin 代码、独立 Python 环境、Qwen3-ASR 模型、心的 GPT-SoVITS 权重/音色配置、正在运行的服务和 GPU 状态。确认能否复用已有环境；不覆盖配置、下载大模型或重启既有服务。
2. 添加 Hsin 专用 PC 语音桥接入口及共用远程客户端；STT/TTS 各新增 `remote` provider，沿用现有后台工作线程、generation、音频校验和播放器。
3. 建议首版使用现有 SSH 身份建立隧道，PC 服务只监听回环地址；Mac 客户端连接本机转发端口。端口待盘点后确定，不要求额外开放 Windows 防火墙。SSH 由本机使用既有私钥认证，不复制私钥到 PC。连接丢失可重建传输，但不自动重放已提交或已播放的语音。
4. 独立桥接服务校验模型/音色身份；不直接复用并切换 Aemeath 正在使用的 GPT-SoVITS 全局音色。优先使用 Hsin 专用进程和配置，避免相互影响。
5. 先测试已有固定 WAV 的识别和一条新句合成，随后接现有聊天分句，最后才进行用户主动开麦的真人验收。

建议协议为 `/health`、`/v1/stt`、`/v1/tts`、预热和作业取消；具体命名在实现时统一。识别上传内存 WAV，返回文本；合成提交文本/语言/音色 ID，返回 WAV。客户端不提交任意 PC 文件路径。每次请求包含会话与请求编号，服务器按模型串行调度；先测显存再决定 ASR/TTS 能否同时常驻。

取消不能仅关闭 HTTP 连接：Mac 必须立即停播并使旧代次失效；PC 取消排队任务。若后端不能中断已运行推理，应如实报告“已忽略结果，推理仍在结束”，不可声称 GPU 已停止。退出 Mac 不终止共享或外部启动的 PC 服务。

## 验收标准

- 固定录音在 PC 实际识别，返回预期中文并记录实际模型和设备。
- 新句经 PC 实际合成，在 Mac 进入 PlayingState 并驱动口型。
- 首句在后续句生成期间播放，后句保持顺序且字幕随实际播放推进。
- 新对话、停止、静音、语言切换和断线后，旧结果不播放、不误发聊天。
- PC 不在线、推理失败和重新连接有明确状态；不会静默转为云端或其他音色。
- 记录冷启动/热状态的上传、排队、推理、首段实际播放时刻，分别衡量网络与模型耗时。
- 服务只使用 RTX 4060，Aemeath 既有语音服务保持正常，Mac 退出释放自身连接和隧道。

## 首版选择

建议第一版采用“PC Qwen3-ASR + PC GPT-SoVITS 心音色 + SSH 隧道”。若 PC 现有已验收的心音色为 Qwen3-TTS，可据盘点结果调整 TTS 后端，Mac 协议与播放器不变。实施顺序为盘点 → 独立服务与客户端 → 固定音频实测 → 聊天逐句播放 → 真人麦克风验收。
