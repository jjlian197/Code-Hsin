# 动作与物理

右键或托盘的“动作”菜单可播放待机、点头、挥手、V 手势、指尖比心和交叉手臂。手势播放一次后自动恢复待机，弯曲的手指也恢复；中途选择其他动作会解除前一个姿态。基础动作在 `motions.js` 中根据真实 PMX 骨骼生成关键帧，不依赖下载的舞蹈素材；关键帧长度在构建时检查，防止异常数据卡住插值器。

动作切换持续保留手臂下垂的待机绑定，在 mixer 完成当前帧后处理结束，不会先回模型原始的平举姿态。挥手使用真实中指、食指、小指骨骼建立掌面坐标系，将掌心朝向 +Z 正面镜头；手腕摆动围绕掌面法线，首尾为相对待机的单位增量。`python -m tools.verify_motion_regressions` 逐帧验证两个形态、物理开关和中途切换，报告位于 `.runtime/motion-regression-validation.json`。

默认开启 Ammo/Bullet 模拟，直接使用 PMX 的原始刚体、碰撞分组和弹簧关节。

| 形态 | 刚体 | 关节 | 关联动态骨骼的刚体 |
| --- | ---: | ---: | ---: |
| 一阶段 | 686 | 947 | 649 |
| 二阶段 | 725 | 1,005 | 690 |

“头发与衣摆物理”开关和“重置物理”位于同一菜单。需要时也可在配置中关闭默认物理：`sprite.animation.physics: false`。关闭不影响动作播放。隐藏窗口会暂停动画和物理，恢复显示后继续计算；较大的时间间隔按最多 0.05 秒推进，避免突然跳跃。

Qt 用 33 毫秒计时器推进帧，不依赖网页是否有焦点；前一帧未完成时不会堆积后续帧。MMDAnimationHelper 处理 AnimationMixer、IK、Grant 和物理。每次加载模型单独初始化 64 MiB Ammo WASM arena；切换后释放旧 arena 的引用，由浏览器回收，避免官方 MMDPhysics 缺少资源销毁入口而在同一 heap 中累计刚体。

## 心的自然反应与口型

两种形态直接使用原 PMX 顶点表情。`behavior.js` 分层组合动作、表情、自动反应和口型，每帧先恢复底层值，避免叠加造成头部角度或表情权重累计。

| 行为 | 适配方式 |
| --- | --- |
| 眨眼 | 原生 `まばたき`；短暂闭合、缓慢睁开，间隔约 2.6–6 秒 |
| 口型 | `あ/い/う/え/お` 对应 a/i/u/e/o；开合平滑，开心表情与嘴角继续保留 |
| 转头 | 首、頭分担小幅旋转；自动水平最大约 22°、垂直约 12°，接口范围单独限幅 |
| 呼吸 | 约 4.7 秒一周期，上半身骨骼轻微起伏 |
| 鼠标跟随 | 每个可见帧读取系统鼠标位置；以当前投影的脸部中心为参照，缓动眼神与头部 |
| 触摸 | 对当前变形网格射线检测；摸头微笑歪头、身体轻摆、手部在待机时挥手、尾巴露出轻微惊讶；附简短气泡 |

模型的 `Left` 表情实际向正面相机的屏幕右移动，已检查两个 PMX 的顶点位移；因此鼠标向右使用 `Left`。眼球移动幅度限制在原表情的 55%（水平）和 45%（垂直），避免眼球越出眼眶。手动视线和参数可以通过接口清除。右键或托盘提供“眼神跟随鼠标”开关、眨眼和停止语音。

本地语音由 `voice_player.py` 的 Qt 播放器解码，`QAudioBufferOutput` 同步取得 PCM 音量，经过静音阈值、柔和增益和开合平滑后驱动张嘴。播放完成、停止或出错时释放音频口型；外部 `lip_sync` 控制有超时，避免断开后嘴一直张着。该方法是音量驱动，尚未逐音素识别；可通过接口选用五种元音口型。中日 GPT-SoVITS 和聊天回复已接入同一播放链路，见 [语音说明](VOICE.md)。

自然骨骼反应在物理计算前叠加，因此头发、衣摆继续跟随；关闭物理后也能眨眼、转头和呼吸。自然反应按实时时间结束，物理仍限制步长，低帧率不会延长触摸与临时口型。外部 VMD 明确写入的骨骼/表情让给该动作控制，结束后恢复自然反应。切换形态会重新映射表情与骨骼，隐藏时暂停帧循环。

可在 `sprite.animation.behavior` 中设置 `auto_blink`、`breathing`、`mouse_follow`、`touch_reactions`、`conversation_actions`、`random_idle`，默认均为 true。

## 对话与陪伴

右键或托盘“陪伴动作”提供对话姿态和随机小动作两个独立开关。菜单开关影响本次运行，长期默认值写入 `config.local.yaml` 的上述配置。

| 状态 | 触发与动作 |
| --- | --- |
| 思考 | 等聊天回复、语音合成或 STT 识别时，轻微歪头、转头和收臂 |
| 说话 | Qt 音频真正播放期间，轻微身体和右手动作；口型独立同步 PCM |
| 倾听 | 麦克风已开启且实际收音、没有被回复阻塞时，微微侧头和前倾 |
| 待机 | 无上述活动时恢复；每次闲置 18–45 秒后随机环顾或轻微伸展约 5.5 秒 |

状态优先级为实际播放 > 回复/合成/识别 > 收音 > 待机。停止、失败和切换后端均根据当前服务状态恢复。手动动作/VMD、触摸、拖动会占用自动姿态，随机动作取消后重新等待；固定视线和头部角度参数也暂停随机动作。自然眨眼、呼吸和衣摆物理继续运行。显式选择的表情保持，对话只在平常表情下叠加轻微面部变化。

“表情”菜单共 12 种：平常、开心、难过、生气、惊讶、眨单眼、困倦、放松、脸红、笑眯眯、星星眼、爱心眼。两个模型均使用自身顶点 morph；缺少原生吐舌，所以没有该菜单项。星星眼与爱心眼适合近距离观察，默认全身尺寸下效果较小。

V 手势已接入。指尖比心与双手交叉目前为初版：用户确认和 Aemeath 原版相差较大，后续需要细化肩肘位置、掌面朝向、指尖关系与整体姿态，两个形态均需重新视觉验收。现有自动验证仅覆盖播放、恢复与物理开关。当前仍使用模型原有衣服刚体，抬臂时袖子可能被带起；大幅伸展、蹲下及复杂衣服自碰撞留待单独适配。

## 本地 VMD

在 `config.local.yaml` 配置现有本地动作文件。例如：

```yaml
sprite:
  animation:
    vmd:
      dance:
        - motions/my-dance.vmd
```

路径以项目根目录为基准，也支持绝对路径。动作组不能占用 idle、nod、wave、tap、peace、finger_heart、crossed_arms 名称。重启后通过控制接口调用：

```json
{"type":"motion","data":{"group":"dance","index":0}}
```

读取后返回 `motion_loading`，查询状态中的 `renderer.info.runtime.motion` 确认实际播放。解析失败会记录 `motion_error`。仅对文件包含的骨骼应用动画，其余骨骼继续待机；外部动作结束后恢复默认待机。后发动作请求会取消前一个尚在加载的动作。重复播放使用缓存，切换模型时清空缓存。

当前验证使用自建的三帧头部旋转 VMD，覆盖真实文件解析、骨骼变化、物理同时更新和结束恢复。复杂舞蹈、腿部 IK、大幅度旋转以及衣服碰撞仍需针对具体文件调试；只构建当前使用的 31 个顶点 morph，VMD 中其他表情会被忽略。

## 检查

```powershell
python -m unittest discover -s tests -v
node tests/test_motion_clips.mjs
node --loader ./tools/node_three_loader.mjs tests/test_behavior.mjs
python -m tools.verify_pmx
python -m tools.verify_behavior
python -m tools.verify_companion
```

检查实际透明背景、脸部不透明、基础骨骼动作、动作结束、物理步数和骨骼变化、关闭后步数停止、重新开启与复位、异步 VMD、双形态切换和背景合成。预览与记录位于 `.runtime/`。

自然反应验证分别加载两个真实模型，检查自然眨眼、呼吸、固定视线、系统鼠标跟随、实际 Qt 鼠标事件与射线命中、参数错误批次、短时口型超时、真实原声音频缓冲和嘴部开合，以及结束闭合、关闭物理后跟随和隐藏暂停。测试原声以零音量播放；结束后恢复鼠标位置，结果为 `.runtime/behavior-validation.json`，预览为 `.runtime/behavior-*.png`。

陪伴验证使用模拟服务状态和本地静音音频，不联网、不打开麦克风，检查两个形态的四种状态、三个新增手势、12 种菜单表情、实际播放/停止信号、结束恢复及物理开关。报告为 `.runtime/companion-validation.json`；原生截图会等待 Qt 合成完成。骨骼与表情的离线检查还覆盖随机动作取消、固定注视优先和开关恢复。
