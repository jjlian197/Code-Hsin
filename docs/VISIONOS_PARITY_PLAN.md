## 已知问题与修复验收

### VOS-FACE-001：眨眼时睫毛不跟随眼睑

- **状态：用户已报告，待开发侧复现与定位，未修复。** 报告日期：2026-10-07；当前版本 Build 5，涉及角色／形态尚未单独确认。
- 现象：眼睑发生眨眼运动时，睫毛没有同步移动，导致眼部表现脱节。
- 排查方向：对比原始 PMX／参考模型与 USDZ 的闭眼形变，检查睫毛网格的 morph 覆盖、分组 morph／骨骼关系和 RealityKit 权重绑定。尚不能认定为缺失素材或某个已确认的转换错误。
- 验收：心一／二阶段及爱弥斯分别观察睁眼、半闭、全闭和重新睁眼；睫毛与眼睑同步，无悬空、穿插或回到睁眼后残留形变。必须核对原生渲染与 AVP 实际外观。

### VOS-FACE-002：嘴形不自然，缺少多种口型

- **状态：用户已报告；单一口型驱动限制已由代码确认，待实现与验收。** 报告日期：2026-10-07；当前版本 Build 5。
- 现象：说话时嘴形变化不自然，需要多种口型。
- 已确认的实现限制：`CompanionStore.advanceFace()` 仅按播放器平均音量驱动 `a` 权重，其他口型被置零；没有多口型选择与混合。这能解释目前能力不足，但不能代替对实际不自然表现的复现。
- 修复目标：核对每个模型实际可用的 `a/i/u/e/o` 等口型与闭嘴形态，迁移适用的 macOS 音频口型逻辑，加入平滑过渡、混合权重及静音回闭嘴；不把缺少形变的模型伪装为完整支持。
- 验收：使用真实中文和日语 TTS，检查多种口型变化、音频同步、过渡自然、静音闭嘴，以及停止／打断／角色切换后没有残留；心两种形态与爱弥斯分别验收。

### VOS-VISUAL-001：模型背后黑框

- **状态：用户已报告，尚未定位。** 爱弥斯 USDZ 的 22 个贴图引用均存在，尚无素材缺失证据。
- 等待 AVP 截图及黑框是否跟随角色移动，区分材质透明度、模型几何体、窗口背景与现实环境。先复现再修改，不统一替换全部材质或降低透明度。

## 平台适配

- macOS 的托盘／右键菜单改为空间工具栏与设置面板；拖动、大小与近景改用系统窗口操作和空间控制。
- 桌面穿透、置顶、Spaces、鼠标屏幕边缘行为没有直接等价的头显行为，不照搬 Qt 窗口策略。
- Three.js／Ammo 的 MMD、Grant、IK、toon 和布料实现无法直接作为 RealityKit 动画运行。先建立匹配 Hsin 骨轴的可重复转换与动作采样，再评估实时物理；不能将爱弥斯专用网格修正套到 Hsin。
- 后端随角色切换：Hsin 使用 PC 上已有 Hermes Agent 的 `default` profile，通过现有 HTTPS 桥接访问；本机保存的 DeepSeek 选择是先前测试配置，不能作为角色默认后端依据；爱弥斯沿用参考 visionOS 的 OpenClaw `agent:main:main`。Hsin 继承其 macOS 角色配置，禁止将爱弥斯的 Agent 会话作为全局默认。角色各自保存后端选择，取消旧任务并分离直连历史；不修改用户 OpenClaw 全局配置。
- 资源仍私有，令牌保存在 Keychain，Mac／PC 保留推理与密钥。新安装及更新默认关闭麦克风。
