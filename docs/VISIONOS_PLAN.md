## 建议首版架构

```text
Vision Pro：SwiftUI / RealityKit、主动录音、字幕、逐句播放、口型
    ↓ 带鉴权的 HTTP / WebSocket
Mac 网关：独立会话、角色设定、聊天、分句、STT 选择、取消
    ↓ HTTPS 域名直连与鉴权（SSH 可选）
PC：Qwen3-ASR + GPT-SoVITS（心 / 爱弥斯，中日文）
```

选择 Mac 网关是为了复用 PC 语音协议与云端配置，头显无需保存 SSH 私钥或聊天 API 密钥。头显会话独立于桌面会话；头显回复不应同时在 Mac 扬声器播放，切换角色也不改变桌面当前角色。

鉴权口令在 Mac 私有文件与头显 Keychain 保存，日志不打印口令。PC 保持回环监听。初次联调仅在用户可信局域网运行 HTTP/WS，并在连接界面明确传输未加密；跨网连接需 HTTPS/WSS。网关有录音长度、消息大小、并发和超时限制。

## 实施阶段与验收

1. **空间角色原型**：新增独立 `visionos/` 工程，先以爱弥斯已有 USDZ 为开发资源验证体积窗口、照明、眨眼、口型与待机；资源保存在私有目录，构建时显式导入。模拟器构建与实际渲染需分别通过。
2. **心模型转换**：建立 Hsin PMX → 中间网格/骨架 → USDZ 的可重复转换工具。检查贴图、材质、坐标、尺寸、骨骼与表情，先通过静态模型和待机，再增加挥手等动作。Aemeath 导出器含特定网格索引修正，不能直接套到心。RealityKit 版本的物理与 toon 外观需另行实现和验收。
3. **语音闭环**：固定新句 → PC 合成 → 头显实际播放 → 口型；再接用户主动录音，STT 可选 PC / 智谱；最后接现有聊天后端。服务端分句、音频返回与实际播放事件分别记录。沿用整句 WAV，不宣称句内 PCM 流式。
4. **角色与取消**：心 / 爱弥斯各绑定模型、设定和音色；请求包含 session_id、turn_id、segment_index、character_id。打断立即停播，切换/断线使旧结果失效。PC 无法中断正在运行的推理时，报告结果已丢弃，不声称 GPU 已停止。
5. **真机验收**：用户主动开麦验证两种 STT、中日 TTS、两角色切换、播放顺序、回声抑制、打断与断线恢复；检查空间尺寸、面部与透明材质、手势点击和应用恢复。

首版为体积窗口。后续 M1 全沉浸空间原型作为下一条开发主线，现有闭环验收并行保留且纳入 M1 回归门槛；实时衣发仍按后续物理阶段处理。启动默认关闭麦克风；回答播放期间暂停收音，避免反馈识别。
