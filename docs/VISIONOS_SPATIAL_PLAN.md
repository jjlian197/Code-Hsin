## M1 架构与坐标约定

```text
HsinVisionApp
├─ Launcher / Control Window
├─ Companion Volume（现有体积窗口）
└─ ImmersiveSpace: hsin-immersive（Full）
   └─ RealityView
      └─ SceneRoot
         ├─ EnvironmentRoot（虚拟地面、灯光、距离参考物）
         └─ SpatialRoot（世界位置、朝向）
            └─ ScaleRoot（物理尺寸校准）
               └─ VisualRoot（模型局部原点与展示适配）
                  ├─ USDZ 骨架 / 网格 / Morph
                  └─ touch target entities
```

- **SpatialRoot** 只控制世界位置和朝向，骨骼动作不能直接驱动它。
- **ScaleRoot** 按模型校准固定物理尺寸；碰撞与交互目标随同一层级变换。微缩模式留给后续设置，移动过程中尺度不变。
- **VisualRoot** 保留导入模型、动画绑定、面部和触摸的局部坐标语义。窗口包围盒取景只用于体积窗口的展示适配；沉浸模式使用独立物理尺寸与地面校准，不能把窗口的 `0.35` 或居中偏移当成真实身高和脚底位置。
- 计划使用米制世界坐标、虚拟地面 `y=0`、初始用户参考原点前方 `-Z`；控制目标为 `(0,0,-4)` 与 `(0,0,-1.5)`。距离相对进入场景时的参考原点，M1 不实时跟随头部重设目标。模型局部正面统一映射到 `+Z`，初始面对原点；各模型原始朝向需在校准时检查。
- 心一／二阶段及爱弥斯分别记录源单位、站姿身高、脚底局部原点和朝向修正。目标物理身高尚未确定，实施校准时记录依据及待确认值，不能从窗口缩放推断。
- 近大远小由固定尺寸实体的世界位移和自然透视产生；不修改缩放制造距离变化。

### 场景、状态与通信生命周期

不同场景建立独立实体实例，同一个 Entity 不同时挂在两个 `RealityView`。M1 优先采用一个活动角色场景：切换模式时明确卸载／重建与代次失效，体积窗口入口继续保留。角色选择、连接和历史等业务状态共享；实体、动画控制器、完成订阅与触摸目标归属具体场景实例。

沉浸空间由控制窗口提供进入／退出操作，处理异步打开失败、用户取消、重复点击与系统退出。单一活动场景驱动面部／互动时钟，避免双重 30 Hz 更新。模式切换停止录音和旧播放，使旧异步结果失效；网关保持单一会话管理，重新进入不会自动开麦。保留 `animationBinding(in:name:)` 对实际骨骼实体的定位、完成事件／控制器完成检查与模型代次保护。

### 移动与姿态的协调策略

- 仅在 `PostureState.phase == .standing` 时接受空间移动。躺下、侧躺、起身时拒绝移动，并给出可观察原因；M1 不增加隐式移动队列。
- 空间移动期间收到躺下／休息请求，先停止世界位移并通过现有动作完成与排队机制进入姿态过渡。显式停止优先于新移动命令，新目标覆盖旧移动目标；模型／形态／模式切换使全部旧目标失效。
- 现有 `treadmill_running` 是原地跑步。先检查根节点动画位移，再选择锁根或提取，确保位移只应用一次；初版可与空间速度同步为移动演示，尚无合适步行动作时不标记“自然步行已完成”。
- 控制器限制单帧位移与角度步长，防止掉帧跳跃、目标附近抖动和多个完成回调重复推进。移动、转向及停止后按实际状态切换动作，不以定时等待代替完成。
